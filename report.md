## Параллельное умножение матриц на суперкомпьютере с использованием MPI  


### Цель работы

Запустить программу параллельного умножения матриц с использованием MPI на суперкомпьютере через систему планирования задач SLURM. Провести замеры времени выполнения для разных количеств потоков (1, 2, 4, 8, 12, 16).

**Примечание**: Верификация корректности результата не была проведена, так как на суперкомпьютере отсутствует библиотека `numpy`, необходимая для сравнения с эталонным результатом (`equivalence.py`). Но этот код уже проходил проверку в 3 лабораторной.


#### 1. Скрипт запуска (`run_intel.slurm`)

Файл `run_intel.slurm` используется для отправки задачи в очередь суперкомпьютера через планировщик SLURM.

```bash
#!/bin/bash
#SBATCH --job-name=lab3_intel          # Название задачи в очереди
#SBATCH --time=00:15:00                # Максимальное время выполнения — 15 минут
#SBATCH --nodes=1                      # Использовать 1 узел
#SBATCH --ntasks-per-node=16           # Запустить 16 процессов/потоков на узле
#SBATCH --mem=8gb                      # Выделить 8 ГБ оперативной памяти
#SBATCH --output=slurm-%j.out          # Лог вывода будет сохранён в файл slurm-[ID].out
#SBATCH --partition=batch              # Использовать раздел "batch" (обычный режим)

export LD_LIBRARY_PATH=/soft/intel_ps/compilers_and_libraries_2018.2.199/linux/mpi/intel64/lib:$LD_LIBRARY_PATH

cd $SLURM_SUBMIT_DIR                   # Перейти в директорию, откуда был отправлен job

echo "=== Start Job ==="               # Вывод сообщения начала выполнения
chmod +x lab3_intel                    # Сделать исполняемым бинарник (на всякий случай)
srun ./lab3_intel                      # Запустить программу через srun (MPI-совместимый запуск)
echo "=== End Job ==="                 # Сообщение об окончании
```

* Ключевые параметры:
  - `--ntasks-per-node=16` — указывает, что программа должна использовать до 16 потоков/процессов.
  - `srun` — запускает программу в рамках выделенных ресурсов, автоматически распределяя потоки по ядрам.
  - `LD_LIBRARY_PATH` — добавляет пути к библиотекам Intel MPI, если они нужны для линковки или динамической загрузки.

#### 5. Вывод

* Влияние количества потоков:
- Конфигурация с 16 потоками показала наилучшую производительность на больших матрицах (2000×2000 — 872 мс против 9767 мс у однопоточной версии, ускорение  в ~11 раз)
- На малых матрицах (≤400) разница между потоками минимальна — это связано с накладными расходами на создание потоков и синхронизацию.
- Начиная с размера 800×800 наблюдается чёткое ускорение при увеличении числа потоков — вычисления начинают доминировать над накладными расходами.

* Накладные расходы (Overhead):
- Для малых матриц (100×100, 200×200) время выполнения почти не зависит от количества потоков. Время тратится преимущественно на создание потоков, синхронизацию и передачу данных.
- Начиная с размера 800×800, наблюдается экспоненциальный рост времени, характерный для алгоритма сложности \( O(N^3) \), где вычисления начинают доминировать над передачей данных.

* Итог:
Использование многопоточности на CPU позволяет значительно ускорить умножение больших матриц по сравнению с последовательным алгоритмом. Оптимальным выбором количества потоков для данной задачи на данном оборудовании является 16, показавший наилучший результат на матрицах размером 2000×2000.
