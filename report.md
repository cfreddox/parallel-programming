# Отчёт по лабораторной работе №4
## Реализация алгоритма перемножения матриц с использованием технологии CUDA

### Цель работы
Разработать программу для умножения двух матриц на графическом процессоре (GPU) с использованием технологии NVIDIA CUDA. Провести замеры времени выполнения для различных размеров матриц и конфигураций блоков потоков, а также выполнить автоматическую верификацию результата.

#### 1. Генерация матриц (`generate_matrix.py`)
- Создание матриц произвольного размера со случайными элементами
- Парсинг аргументов командной строки:
  - Файл для записи
  - Размеры матрицы (строки, столбцы)
  - Диапазон значений элементов
- Сохранение матриц в текстовые файлы с указанием размерности

#### 2. Основной алгоритм (`main.cu`)

- Чтение данных
Функция `readMatrix()` считывает размеры $N, M$ и элементы матрицы из файла в динамический массив хоста.

- Ядро умножения (`MatrixMultiply`)
Реализовано стандартное ядро умножения матриц C = A \times B:
*   Каждый поток вычисляет один элемент результирующей матрицы C.
*   Индексы определяются через `blockIdx`, `threadIdx` и размеры блока.
*   Используется проверка границ: `if (col < N && row < M)`.

- Управление памятью и запуск
Функция `multiplyMatricesCUDA`:
1.  Выделяет память на устройстве (`cudaMalloc`) для матриц A, B, C.
2.  Копирует входные данные с хоста на устройство (`cudaMemcpy HostToDevice`).
3.  Рассчитывает конфигурацию сетки (`grid`) и блоков (`block`).
4.  Запускает ядро.
5.  Синхронизирует выполнение (`cudaDeviceSynchronize`) для корректного замера времени.
6.  Копирует результат обратно на хост (`cudaMemcpy DeviceToHost`).
7.  Освобождает память устройства (`cudaFree`).


#### 3. Верификация результата (`equivalence.py`)
- Считывание исходных матриц из тех же текстовых файлов
- Сравнение результата с эталонным умножением через `numpy.dot()`
- Возврат кода: `0` - результаты совпадают, `1` - обнаружено расхождение

#### 4. Результаты замеров производительности

Замеры проводились на GPU **NVIDIA GeForce RTX 3050 Laptop GPU** (Compute Capability 8.6, 16 SM).
Время измерялось полностью, включая копирование данных и выделение памяти, в миллисекундах для полной доставерности результатов.

#### 6. Вывод

1.  **Влияние размера блока:**
      Конфигурация (16, 16) показала наилучшую производительность на больших матрицах, все конфигурации больше показали такой же результат или хуже, поэтому не стал добавлять в отчёт. Видно, что с ростом матриц, привосходство по скорости увеличивается над другими конфигурациями.
    

2.  **Накладные расходы (Overhead):**
    *   Для малых матриц (100x100, 200x200) время выполнения почти не зависит от размера блока. Время тратится преимущественно на передачу данных, а не на сами вычисления.
    *   Начиная с размера 800x800, наблюдается линейный рост времени, характерный для алгоритма сложности $O(N^3)$, где вычисления начинают доминировать над передачей данных.

3.  **Итог:**
    Использование GPU позволяет значительно ускорить умножение больших матриц по сравнению с последовательным CPU-алгоритмом. Оптимальным выбором размера блока для данной задачи на архитектуре Ampere (RTX 3050) является 16x16, показавший наилучший результат.
